# Deployment and maintenance

Use Node.js 24 (pinned to `24.x` in `package.json`) and a clean `npm ci`. `npm run build` generates fallback monogram assets and writes a versioned service worker from the compiled browser chunks, CSS and fonts using Next’s `compiler.runAfterProductionCompile` hook. This runs before static page generation and before Vercel’s adapter packages public files, so the deployed worker includes the current assets without depending on internal prerendered HTML paths. There is no npm postbuild step. Deploy the completed build and its `public` directory together. The build uses Next's font downloader; it needs network access to the font source at build time, not at visitor runtime.

The production suggestion form requires only `DISCORD_WEBHOOK_URL`, which delivers suggestions directly to Discord. No database or additional storage service is required. For optional shared spam counters, set `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` (Vercel's `KV_REST_API_URL` / `KV_REST_API_TOKEN` aliases also work). Never prefix these values with `NEXT_PUBLIC_`. See `.env.example`. Redis must support EVAL, INCR, PEXPIRE, PTTL, EXISTS, SET and DEL. Store commands have a four-second deadline. When no store is configured, bounded expiring memory provides best-effort rate/duplicate checks in development and production. These counters reset on server restarts and are not shared across serverless instances. If an optional store is explicitly configured but unreachable, the request returns a helpful 503 rather than silently weakening the selected shared protection.

On Vercel the rate limiter uses the provider-overwritten `x-forwarded-for` header. Other hosts deliberately use one shared limit until a trusted proxy integration is explicitly implemented. Do not add caller-controlled headers as a preferred identity. Limits allow five attempts per 15 minutes; names and normalized URLs are hashed and reserved atomically for 24 hours. An explicit Discord rejection releases the reservation. An ambiguous network timeout retains it to avoid duplicate delivery and returns a receipt. This is confirmed delivery with deduplication, not a guaranteed-delivery queue. A real durable outbox can be added if the product needs that guarantee.

The metadata fetch proxy was removed. Do not reintroduce arbitrary outbound URL fetching for previews. The catalog uses its original image URLs. The CSP image allowlist includes those existing image origins; fallback monograms are generated locally.

The CSP enforces same-origin scripts/assets, blocks plugin objects and framing, restricts forms and base URLs, and permits the performance-reporting endpoint. Static Next pages require inline Flight bootstrap scripts, so the enforced policy currently permits inline scripts; a stricter `script-src 'self'` policy runs in report-only mode. This is intentionally not represented as a fully strict inline-script CSP. Promoting it requires a separately tested hash/build integration or request nonces with their static-rendering tradeoff. Do not promote the report-only directive unchanged: it would break hydration. Check the actual deployed response headers after release, especially if a CDN modifies them.

Page-view analytics were removed. Speed Insights remains on Vercel production and strips query strings/fragments before reporting URLs. No discovery queries are sent to an analytics service. Before adding outcome analytics, define consent/retention and an aggregated event schema; avoid raw search text and personal URL parameters.

Run `npm run lint`, `npm test`, `npm run build`, `npx tsc --noEmit`, `npm audit --omit=dev`, and `npm run test:e2e`. The browser suite launches a production server on 3100. It uses installed Chrome on macOS and Playwright Chromium on Linux. Browser snapshots/test traces stay in ignored `test-results/`.

GitHub Actions workflows and the Dependabot configuration were removed at the owner’s request. Run quality checks, link reviews and dependency updates locally; Vercel handles deployment builds. A link-check report distinguishes confirmed HTTP 404/410 failures from 403/429/timeouts that need human review. Listings with a verified unavailable destination are disabled rather than linked to a guessed replacement. Keep their IDs so existing favorites remain recognizable. Update the checked-in review document when acting on a report.

Catalog records now carry persistent IDs, dates and topic arrays. Keep existing IDs when renaming tools. Add new IDs to `src/data/catalog-ids.ts`; catalog integrity checks require the registry and records to agree. Add sourced facts in `comparison-details.ts`, and keep unknown fields unset. Never infer an open-source license from a GitHub organization/repository link. Legacy tool query/hash URLs and earlier shared stack hashes remain supported.

Before publishing, verify the new build on the hosting preview with the existing Discord webhook: accepted suggestion with a test channel, rate-limit response, duplicate expiry, live headers, the install icon, and an offline reload after the service worker activates. No real Discord suggestion was sent during the local implementation tests.

The original visual design was restored at the owner’s request. Preserve its typography, otter introduction, navigation, cards, dialogs, submission layout, motion and catalog artwork. Security/submission logic, stable catalog IDs, text export, static detail routes, the Vercel build hook and the disabled GitHub Actions setting remain. Browser tests now target the restored interface across four widths.
